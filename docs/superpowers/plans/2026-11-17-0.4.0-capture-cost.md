# 0.4.0 Part 2: Bound the Cost of Content Capture — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With content capture on, a run costs about its history once, not steps × history: the mask runs once per distinct string, a run's step inputs stay under a budget, and stored trees take several times less room.

**Architecture:** Three independent layers, cheapest and safest first.
1. A per-flush memo inside `Content` dedupes mask-and-cut. Output is unchanged.
2. A per-run budget in `RecordAgentRuns` switches step inputs to "new messages only" past 2 MB, and marks the run `laravel.ai.content_truncated`.
3. `TreePayload` gzips stored trees behind a text prefix, so trees stored by 0.3 still decode.

Two small collector fixes from the review's "Also found" table ride along.

**Tech Stack:** PHP 8.3+ with `ext-zlib`, Laravel 12/13, Pest, Pint, PHPStan.

**Spec:** Triage doc, section **3. Bound the cost of content capture**, plus the last two rows of **Also found**: https://claude.ai/artifact/9MHQ2t5BMebMr7DpCbUEF7

## Global Constraints

- Nothing Refract does may throw into the app. No new environment variables. New limits are constants.
- The memo is capped at **4 MB** of masked values. The per-run budget is **2 MB** (`2_097_152` bytes) of step input content.
- The marker text is exactly `[{N} earlier messages omitted, see step 1]`. The run attribute is exactly `laravel.ai.content_truncated` = `true`.
- Run input, run output, tool arguments, tool results and step outputs are never cut by the budget.
- A run under the budget records exactly what 0.3.0 records. The workbench expected trees (`workbench/expected/*.txt`) do not change.
- Stored format: `gz1:` + base64(gzencode(json, 6)). A payload not starting with `gz1:` is decoded as plain JSON.
- Each task updates `README.md` (the content capture and store sections) and `CHANGELOG.md` under `## [Unreleased]`.
- Finish every task with `vendor/bin/pint`, `composer analyse` and `vendor/bin/pest --parallel`, all green.

## Review Focus

1. **A mask that is not pure** (it adds a timestamp or a random token). The memo would return the first result for every repeat. The README must say masks are assumed deterministic per run. → Task 1 test `a value is masked once per flush, even by a mask that is not pure` pins and documents that behaviour.
2. **A conversation loaded from the SDK's store, whose first step is already over budget.** Step 1 must still record its full input, and only the later steps are cut. → Task 2 test `a run whose first step is over budget keeps step 1 whole`.
3. **Nested agents (an agent calling a sub-agent).** Each run has its own budget and its own "previous step" message count. → Task 2 test `a sub-agent's budget is its own`.
4. **A 0.3.0 tree still stored in Redis or the database when 0.4.0 deploys.** It must decode and export. → Task 3 test `a plain tree stored by 0.3 still decodes`.
5. **The database collector on PostgreSQL or MySQL with a `longText` column.** Raw gzip bytes would break (NUL bytes, invalid UTF-8). The base64 text prefix avoids that. → Task 3 test `a compressed payload is plain ASCII`.

### Task 2: A per-run budget for step inputs

**Files:**
- Modify: `src/Capture/RecordAgentRuns.php` (`startingStep()`, line ~224; clear state in `agentPrompted`, `agentFailed` and the existing `flushing` reset), `src/Capture/Content.php` (constant only), `src/Capture/Recorder.php`, `src/Export/GenAiTranslator.php` (next to the `laravel.ai.truncated` line ~87)
- Test: `tests/Feature/ContentTest.php`, `tests/Unit/GenAiTranslatorTest.php`

**Interfaces:**
- Produces:
  - `Content::RUN_BUDGET = 2_097_152`.
  - `RecordAgentRuns` keeps, per run key, `array{bytes: int, messages: int}`: the step input bytes recorded so far, and the message count of the previous step.
  - In `startingStep()`, once `bytes` has reached `RUN_BUDGET`, it records `stepInput(array_slice($event->messages, $messages))`, preceded by one message `['role' => 'system', 'parts' => [['type' => 'text', 'content' => "[{$messages} earlier messages omitted, see step 1]"]]]`, and calls `Recorder::markContentTruncated($runKey)`. Bytes are measured as `strlen(json_encode($content['input'] ?? []))`. Step 1 is never cut, whatever its size.
  - `Recorder::markContentTruncated(string $key): void` sets `call.content_truncated = true` on the run's top-level span when it ends, the way the existing `$truncated` set works (lines ~72–76, 252).
  - `GenAiTranslator` maps `call.content_truncated === true` to `laravel.ai.content_truncated: true`.

### Task 3: Compress stored trees

**Files:**
- Modify: `src/Transport/Collectors/TreePayload.php`, `composer.json`
- Test: `tests/Feature/TreePayloadTest.php` (new), plus the existing collector tests

**Interfaces:**
- Produces:
  - `TreePayload::encode(array $tree): ?string` returns `'gz1:'.base64_encode(gzencode($json, 6))`.
  - `decode(string $payload): ?array` gunzips when the payload starts with `gz1:`, and otherwise takes it as JSON.
  - A payload that fails base64 or gzip decoding returns null, which the collectors already drop as `decode`.
  - Callers are unchanged. The cap, the Lua byte count and `bytes` now count the compressed size.

  - `a 1.5 MB text tree stores in under a third of its JSON size`: build the content from `str_repeat` of a few varied English sentences, not random hex, so the ratio is stable.
  - `a corrupt gz1 payload decodes to null`.

### Task 4: Collector fixes (running total, claim paging)

**Files:**
- Modify: `src/Transport/Collectors/DatabaseCollector.php` (`push()` line ~100, `storedBytes()` line ~257), `src/Transport/Collectors/RedisCollector.php` (`CLAIM` script)
- Test: `DatabaseCollectorTest.php`, `RedisCollectorTest.php`

**Interfaces:**
- Produces:
  - **Database:** `push()` reads the running total from cache key `refract:database:bytes`, and only runs `SUM(bytes)` when that key is missing.
    - The total is reconciled with `SUM` on every `claim()`, and in any case at most 60 s after the last reconcile. Store the time in `refract:database:bytes:at`.
    - `push`, `ack` and a claim that drops a decode failure adjust the total with `increment` / `decrement`.
    - When the cache fails, it always uses `SUM`, as today.
  - **Redis:** the `XAUTOCLAIM` loop in `CLAIM` uses `COUNT 100` instead of `COUNT 1`, and the byte check after each entry stays the same.
    - `XAUTOCLAIM` resets the idle time of every entry it returns. So when the byte limit is reached part way through a batch, the entries left over must be made claimable again. `XCLAIM` them back with `IDLE {lease × 1000}`, otherwise they would wait a whole lease.

- [ ] **Step 1: Write failing tests**
  - `a push does not sum the table while the running total is fresh`: `DB::listen` counts queries containing `sum(`. 10 pushes give 1.
  - `the total is reconciled on claim, so a row deleted behind the collector's back frees its bytes`.
  - Redis: `250 expired leases are all claimed in one claim, in order`.
  - Redis: `leases left over when the byte limit is hit part way through a batch are claimable at once`. Claim with a limit that fits 30 of 100 expired trees, then claim again straight away, with no time travel. Expect the next 30.
