# 0.4.0 Part 1: Make Trace Loss Visible — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Someone running Refract can tell, from a command, an event or a log line, that traces are being lost and why, in every process model (FPM, queue worker, console).

**Architecture:** One loss path, `Diagnostics::dropped()`, records every dropped tree three ways: a durable counter in the app's default cache (`Stats`), a `TracesDropped` event, and a rate-limited warning. Collectors gain an optional `ReportsStats` contract. `refract:status` reads it all and exits non-zero when unhealthy. `refract:test` sends one synthetic trace. Two queue-drain bugs from the review's "Also found" table ship here because `refract:status` reports what they fix.

**Tech Stack:** PHP 8.3+, Laravel 12/13, Pest, Orchestra Testbench, Pint, PHPStan (`composer analyse`).

**Spec:** Triage doc "Refract 0.2.0: three improvements…", section **2. Make trace loss visible**, plus the first two rows of **Also found**: https://claude.ai/artifact/9MHQ2t5BMebMr7DpCbUEF7

## Global Constraints

- Nothing Refract does may throw into the app. Every cache, event and log call is wrapped, and a failure falls back to process memory or is skipped.
- No new environment variables. Refract keeps its ten. New limits are constants, like `Content::MAX_BYTES`.
- Every cache key starts with `refract:`.
- Warnings keep the `[refract] ` prefix and go through `Diagnostics`.
- The stall threshold is **10 minutes** (600 s). The warning window is **10 minutes** per key.
- Each task updates `README.md` and adds a `CHANGELOG.md` entry under `## [Unreleased]` for what it changes.
- Finish every task with `vendor/bin/pint`, `composer analyse` and `vendor/bin/pest --parallel`, all green.

## Review Focus

1. **A `TracesDropped` listener that throws, or that runs an agent.** The drop must still be counted and the app must not see the exception. A listener that runs an agent must not recurse into another drop event. → Task 2 test `a listener that throws or records another drop does not break or recurse`.
2. **The default cache is the `array` driver (or fails), under FPM.** Counters reset every request. `refract:status` must say so instead of reporting "0 dropped" as healthy. → Task 5 test `status warns that counters are per process when the cache is array`.
3. **A long-lived queue worker during a days-long outage.** The full-store warning must come back every 10 minutes with a count, not just once. → Task 3 test `a worker warns again after 10 minutes with the count since the last warning`.
4. **`refract:status` run on a sync-drain app** (no collector, no Redis). It must not try to connect to Redis. It shows the breaker and the last success instead. → Task 5 test `status on the sync drain does not make a collector`.
5. **A retryable failure on the second request of a multi-request drain.** Trees already accepted must not be sent again. → Task 7 test `a 503 on the second request acks the trees the first one delivered`.

### Task 3: Rate-limited warnings

**Files:**
- Modify: `src/Support/Diagnostics.php`
- Test: `tests/Feature/DiagnosticsTest.php`

**Interfaces:**
- Produces:
  - `Diagnostics::WINDOW = 600`.
  - `warn()` logs a key at most once per window, shared through the cache with `add("refract:warned:{key}", true, WINDOW)`.
  - The calls suppressed meanwhile are counted with `increment("refract:warned:{key}:count")`. The next logged warning ends with ` ({N} more since the last warning)` and resets the count. Nothing is appended when N is 0.
  - When the cache fails, the process keeps `array<string, int>` last-logged times and counts.
  - Remove `MAX_KEYS`.
- Tests call `Diagnostics::reset()`, which clears the process state; `TestCase` already calls it.

### Task 4: Collector stats, and the stall warning

**Files:**
- Create: `src/Contracts/ReportsStats.php`
- Modify: `RedisCollector.php`, `DatabaseCollector.php`, `src/Transport/Drain.php` (`collect()`)
- Test: `tests/Feature/CollectorStatsTest.php`. The Redis cases go in `RedisCollectorTest.php`, which skips without Redis.

**Interfaces:**
- Produces:
  - `interface ReportsStats { /** @return array{trees: int, bytes: int, max_bytes: int, oldest_age: ?int, dropped: ?int} */ public function stats(): array; }`.
  - `oldest_age` is the seconds since the oldest tree that is due now became due. It is null when nothing is due.
    - Redis: the minimum of the first stream entry's id time (`XRANGE key - + COUNT 1`) and the smallest due score in the delayed zset, in one Lua script.
    - Database: `MIN(available_at)` where `available_at <= now`.
  - `dropped` is the Redis Lua counter, or null for the database collector.
  - `Drain::STALL_AFTER = 600`.
  - After a successful push, `Drain::collect()` checks `stats()['oldest_age']`. It checks at most once per 60 s across processes (`add('refract:stall:checked', true, 60)`). Past `STALL_AFTER` it warns key `drain.stalled` with exactly:
    `No worker is draining the refract queue: the oldest stored tree has waited {M} minutes. Run queue:work with --queue=default,refract, or add refract to your workers' queues.`

  - `with no worker, the stall warning logs once after 10 minutes`: queue drain, `Queue::fake()`, push, `travel(601)`, push again, push a third time. Expect exactly one `drain.stalled` line.
  - The same pair for Redis in `RedisCollectorTest.php`.
